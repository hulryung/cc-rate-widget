# v1.11.0

Anthropic's real percentages now reach the app the documented way, and the popover is down to
the three windows that mean something.

---

## Official percentages, without the Keychain

Claude Code hands its [status-line command](https://code.claude.com/docs/en/statusline) a JSON
payload that includes `rate_limits.five_hour` and `.seven_day` — the same figures `/status`
prints, with their reset times. Have your status-line script write that block out and this app
reads it:

```bash
crm_dir="$HOME/Library/Application Support/Claude Rate Monitor"
printf '%s' "$input" | jq -e '.rate_limits | objects | (has("five_hour") or has("seven_day"))' >/dev/null 2>&1 &&
  mkdir -p "$crm_dir" &&
  printf '%s' "$input" | jq -c '{written_at: (now | floor), rate_limits: .rate_limits}' \
    > "$crm_dir/.statusline-usage.tmp" &&
  mv -f "$crm_dir/.statusline-usage.tmp" "$crm_dir/statusline-usage.json"
```

No login, no token, no network call of its own, and **no Keychain prompt** — the numbers arrived
with a response Claude Code had already made. The footer reads **official · status line**.

**Why this replaced the old route.** Reading Claude Code's OAuth token from the Keychain was never
just an undocumented endpoint. macOS gates that item on a partition list as well as a trusted-app
list, and granting one program access narrows the list against the other — so this app and Claude
Code took turns being prompted, and "Always Allow" could not settle it. The Keychain path survives
as a fallback, off unless you turn it on, and used only when status-line data is missing or over an
hour old. Stale data is discarded rather than shown: a percentage from before a window rolled over,
presented as current, is worse than none.

## Three windows, each with a bar

The popover now shows the all-model week, **Fable**, and the 5-hour session — and every one of them
has a gauge.

Opus and Sonnet lose their cards. They draw down the same all-model week the top card already
shows, so a second bar for either was the same quota counted twice; `/status` doesn't list them
separately either. Fable stays because Anthropic meters it against a limit of its own.

Fable's bar comes from extending the weekly self-calibration per model family: seven days at the
pace of that family's heaviest whole day, measured against its own days rather than a share of the
total. A model used in short bursts would otherwise read as permanently idle.

When Anthropic's percentages are available, the per-model card is recut over Anthropic's block
along with the weekly card. Left on the rolling seven days it contradicted the card above it — an
early build printed "Weekly 55.71M" over "Weekly · Opus 63.45M", a total smaller than one of its
own parts.

## The footer says whose numbers these are

The signed-in account now appears beside the source: `official · status line · you@example.com`.
It comes from `oauthAccount` in `~/.claude.json`, a file read cached against the file's
modification date.

## Settings is gone

Window, menu item, <kbd>⌘</kbd><kbd>,</kbd> and the popover button. Nothing in it survived the
changes above: percentages calibrate themselves, the status-line path is opted into by writing the
file, and **Grant Access** already had a copy in the popover's setup prompt.

Anything you had set is still honoured, and still changeable:

```bash
defaults write com.dkkang.cc-rate-widget weeklyLimitMillions -float 91
defaults write com.dkkang.cc-rate-widget hotkeyEnabled -bool false
defaults write com.dkkang.cc-rate-widget oauthEnabled -bool true
```

---

Upgrading is nothing but replacing the app: same bundle identifier, same storage, no migration.
