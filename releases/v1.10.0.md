# v1.10.0

**The app is now Claude Rate Monitor.** Same app, same data, new name.

---

## Why

The desktop widget was removed in 1.8 for structural reasons — a sandboxed extension cannot
keep an App Group entitlement without a provisioning profile validating it — and the name has
been promising it ever since. What is left is a menu-bar item that monitors usage, so that is
what it is called.

## What this means for you

- **The app in Applications is `Claude Rate Monitor.app`.** Installing over an older version
  leaves the old `Claude Rate Widget.app` behind; Homebrew removes it for you, and if you
  installed from the DMG, drag the old one to the Trash.
- **Your settings, limits and Keychain permission survive.** The bundle identifier is
  deliberately unchanged. It is what macOS keys your preferences and the Keychain grant on, so
  renaming it would have reset both and made macOS prompt you again for access to Claude Code's
  login. Nobody ever sees it, so it keeps the old name.
- **Your usage history comes with you.** Storage moved to
  `~/Library/Application Support/Claude Rate Monitor/`, copied across on first launch under the
  rule the earlier migration already used: only files you don't already have, never an
  overwrite. The old folder is left in place, so going back to 1.9.0 finds its data intact.
- **Homebrew:** the cask is now `claude-rate-monitor`. If you installed under the old token,
  `brew upgrade` follows the rename on its own — a `cask_renames.json` entry in the tap points
  the old name at the new one. Newer Homebrew may ask you to trust the cask again, because a
  renamed token counts as a new one.

      brew install hulryung/tap/claude-rate-monitor

- **The DMG is `ClaudeRateMonitor-v1.10.0.dmg`**, signed with the same Developer ID certificate
  and notarized by Apple as before.

## The homepage moved

[rate.hulryung.com](https://rate.hulryung.com/). The old address never reached this project —
it resolved to a redirect that sent everyone to an unrelated site — so anything pointing at it,
including the link in this repository's own README, was landing readers somewhere else
entirely.

---

## Nothing else changed

No behaviour, no numbers, no windows. 1.9.0's weekly self-calibration — the bar that appears
without your entering a limit — works exactly as it did. If you are coming from 1.8.0, that
feature is new to you: see the [1.9.0 notes](https://github.com/hulryung/claude-rate-monitor/releases/tag/v1.9.0).
