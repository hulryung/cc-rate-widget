# v1.8.0

Coming from **v1.5.2**? Everything below lands at once, because v1.7 was never published: the
move off the Anthropic API onto your local logs, then the removal of the desktop widget.

---

## The desktop widget is gone

**This is the breaking change.** If you have the Claude Rate Widget on your desktop, it will
not come back — remove it. The reason is structural: a sandboxed extension needs a
provisioning profile to keep its App Group entitlement, and dropping the sandbox stops
WidgetKit registering it at all.

**The main window is gone too.** It duplicated the popover, and closing it quit the app. Its
one unique piece, the per-project breakdown, moved into the popover.

### What you get instead

- **The menu bar.** A gauge icon plus your weekly figure — a percentage when a limit is
  known, an abbreviated token count when one isn't. There is no toggle to hide it, because a
  switch that hides the only way to reach the app is a footgun.
- **The popover.** Click the menu-bar item for the full picture: one card per rate-limit
  window with tokens, cost, a usage bar and a reset time, then **Projects · last 7 days** —
  your top 20 projects by tokens and cost. Opening it activates the app, so
  <kbd>⌘</kbd><kbd>R</kbd> (Refresh) and <kbd>⌘</kbd><kbd>,</kbd> (Settings) work at once. It
  dismisses on <kbd>Esc</kbd>, a click outside, a second click of the menu-bar item, or on
  losing focus. Right-click for Refresh Now / Settings… / Quit.
- **<kbd>⌥</kbd><kbd>⌘</kbd><kbd>U</kbd>.** The same windows anywhere, stripped to a glance.
  On by default; turn it off in Settings.

There is no Dock icon and no main window. The menu bar is the app.

## Actual cost was about 35% more than we reported

The pricing table only matched the Claude 4 generation, so **every Claude 5 model — Opus 5,
Sonnet 5, Fable 5 — was costed at $0** while its tokens still counted. Cache writes were
billed at 1.25× input when Claude Code now writes 1-hour entries at **2×**. Across 7 days of
real logs: **$1,739.15 reported vs $2,355.76 actual**.

Recorded usage carries a precomputed cost, so corrected pricing can't repair it in place.
**The store version was bumped, so your events are re-read from your logs on first launch**,
skipping files untouched since the 7-day cutoff.

---

## Real tokens and dollars, from your own logs

If you're on v1.5.2, this is the largest change. The app used to sign into your Anthropic
account and poll the usage API. It now reads the JSONL transcripts Claude Code already writes
to `~/.claude/projects/`, deduplicated on the same `messageId:requestId` key `ccusage` uses.

- **No account to connect, no API keys, no OAuth login.**
- Actual token counts and USD cost per window, not estimates against an inferred limit.
- **Per-project attribution** for the last 7 days.
- **Nothing prompts you at launch.** If `~/.claude/projects` is already readable, you are
  never asked. If it isn't, the popover shows "Setup required" with a **Grant Access** button
  that opens a folder panel pinned to `~/.claude/projects`. Settings keeps the same button so
  you can trigger it again later.

### Percentages are optional, and honest about what they measure

**Enter your plan's 5-hour and weekly token limits in Settings to see a percentage against
them.** Leave them blank and the weekly window shows absolute usage only.

The session window is the exception. Left blank it self-calibrates against the P90 of your
own past 5-hour blocks, which needs three prior blocks before any percentage appears at all.
It is labelled **"of your typical peak"**, never presented as Anthropic's quota.

## Windows now follow what Anthropic actually reports

The app used to hardcode session, weekly and weekly-Sonnet, so it missed the per-model windows
Anthropic had grown and kept drawing the retired Sonnet one as 0%. The list is now discovered,
weekly first and session last.

- **With official usage on**, it mirrors Anthropic's own, including scoped per-model windows
  (e.g. "Weekly · Fable") that come and go by account and over time.
- **With official usage off**, you get a 7-day window, a 5-hour session window, and one
  "Weekly · *Family*" window per model family present in your logs, largest first.

## The <kbd>⌥</kbd><kbd>⌘</kbd><kbd>U</kbd> HUD was rebuilt

It used to reuse the popover, which is a thing you browse. The HUD is now built for a glance,
ordering what matters in that moment: the percentage, how long is left, when it resets. The
first window carries the big numeral at 44pt; every window below repeats it at 17pt.

Without a percentage, that large numeral is your token count and there is no usage bar. It
stays that way until you enter your limits in Settings.

**It stays up for 5 seconds**, not three, which was too short once the window list became
variable-length. It waits if your pointer is over the panel. Press
<kbd>⌥</kbd><kbd>⌘</kbd><kbd>U</kbd> again to dismiss it early; the hotkey is system-wide, so
that always works.

Unlike the popover, the HUD deliberately does *not* activate the app, so it never steals
focus. The cost is <kbd>Esc</kbd>, which works only when the app is already frontmost.

## Official usage percentage (experimental, opt-in, off by default)

When enabled, the app reads Claude Code's existing OAuth token from your login Keychain and
calls Anthropic's `/api/oauth/usage` endpoint to show their real quota percentage.

**This is not a supported public API.** It may return `401`/`403` or change without notice,
and Anthropic's terms discourage third-party use of that login; the warning now sits in
Settings, not a footer. The app never refreshes the token and never writes it to disk, and
falls back to your local data whenever the request is unavailable.

**The Keychain is now read once per launch, not every 15 minutes.** Reading it is what raises
the macOS permission prompt, and 15-minute refreshes meant roughly 96 reads a day. The fetch
is still throttled, but keyed on the last *attempt*, so a denied prompt no longer re-prompts
every tick.

## Also in this release

- **A real Settings window**, from the popover's **Settings…** button or the right-click
  menu: the two token limits, the <kbd>⌥</kbd><kbd>⌘</kbd><kbd>U</kbd> toggle (on), official
  usage (off), and a button to re-prompt for `~/.claude` access. <kbd>⌘</kbd><kbd>,</kbd>
  opens it while the popover or Settings is frontmost, but can't be system-wide.
- **Number formatting.** 1,400 tokens used to render as "1K", a 29% error on a headline
  figure. Costs now use locale grouping and drop cents above $100.
- The app no longer asks for notification permission it never used.

## Upgrading

Storage moves from the App Group container to
`~/Library/Application Support/Claude Rate Widget/`. Your state files and settings are copied
out on first launch, but only where nothing is already there, so anything set locally is left
alone. Coming from v1.5.2, the first thing you'll notice is that there is nothing to log into.

**Requires macOS 14.4 or later.**

---

## Installing

**Homebrew:** `brew install hulryung/tap/claude-rate-widget`, or `brew upgrade` if you already
have the cask. The tap is bumped automatically when this release is published.

**DMG:** attached below. Both the DMG and the app inside it are signed with a Developer ID
certificate and notarized by Apple, so Gatekeeper opens it without a trip through System
Settings — the previous release predates that and this one was verified under quarantine before
publishing.

Or build from source:

```bash
xcodegen generate
xcodebuild build -project CCRateWidget.xcodeproj -scheme CCRateWidget -configuration Release \
  CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO CODE_SIGN_IDENTITY=""
```

`xcodegen` is required — the Xcode project is generated and not committed. The signing
overrides let you build without the project's pinned Developer ID team; drop them if you hold
that certificate.
